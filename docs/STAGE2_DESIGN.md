# 第二阶段增量系统设计

本设计保存第二阶段增量决策及实施记录，配合 STAGE2_REQUIREMENTS.md 使用。里程碑 0–6 已通过人工确认；当前完整系统见 SYSTEM_DESIGN_STAGE2.md，完整字段与索引见 DATABASE_DESIGN.md，接口见 API.md。本文早期方案比较保留为设计演进依据，不代表功能仍未实现。

## 新需求对第一阶段设计的冲击

| 需求        | 第一阶段不再足够的假设       | 数据与程序变化                             | 兼容性                                     |
| ----------- | ---------------------------- | ------------------------------------------ | ------------------------------------------ |
| R1 复用     | 题目只属于一个问卷快照       | 独立题目身份和版本，选题保存来源映射       | 原实例 ID、答案与快照读取不改              |
| R2 共享     | 所有资源只由问卷所有者使用   | 批量且按版本授权，增加访问检查与另存       | 共享不改变原问卷权限，不授予回答读取       |
| R3 修改隔离 | 问卷版本不可变已足够保护内容 | 库版本被采用时冻结，未采用可修改           | 已发布问卷和既有快照永不自动更新           |
| R4 历史     | 只有问卷版本历史             | 题目父版本、恢复来源和内容 revision        | 不改问卷版本号和生命周期                   |
| R5 并存     | 问卷实例 ID 足以标识题目     | 独立版本并存，稳定来源选项 ID              | 本地实例选项仍独立生成                     |
| R6 使用情况 | 只按所有者查询问卷即可       | 跨所有者脱敏引用查询，D8 评估反向索引      | 仅源题所有者可见受限汇总，不暴露问卷和回答 |
| R7 题库     | 题目编辑入口只有问卷草稿     | 分类成员、跟随或固定策略及更新操作         | 更新库成员不更改问卷快照                   |
| R8 统计     | 全部统计只需指定一个问卷版本 | 来源映射、版本选择合并、选项归一和数字分桶 | 原统计接口与旧数据归属保留                 |

## 集合与字段

保留原五集合。题目有限选项与校验内嵌，历史、授权、题库成员独立存储；不把全部使用者或回答嵌入题目身份文档。

| 集合                  | 主要字段                                                                                                                                   | 约束与访问                                                               |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------ |
| `questions`           | `_id`, `ownerId`, `type`, `latestVersionId`, `nextVersionNumber`, `revision`, `copiedFrom`, 时间                                           | 对外身份为 `libraryQuestionId`；所有者分页；版本序列条件更新             |
| `question_versions`   | `_id`, `libraryQuestionId`, `versionNumber`, `contentRevision`, `frozenAt`, `parentVersionId`, `restoredFromVersionId`, `definition`, 时间 | `(libraryQuestionId, versionNumber)` 唯一；冻结后禁止改定义              |
| `question_shares`     | `_id`, `libraryQuestionId`, `questionVersionId`, `recipientId`, `accessRevision`, 时间                                                     | `(questionVersionId, recipientId)` 唯一；支持接收者列表和批量授权        |
| `question_banks`      | `_id`, `ownerId`, `name`, `revision`, 时间                                                                                                 | 所有者分页及并发保护                                                     |
| `question_bank_items` | `_id`, `bankId`, `libraryQuestionId`, `versionPolicy`, `questionVersionId`, `revision`, 时间                                               | `(bankId, libraryQuestionId)` 唯一；pinned 必须有版本，latest 无固定版本 |
| `question_usages`     | `ownerId`, `surveyId`, `surveyVersionId`, `questionId`, `libraryQuestionId`, `questionVersionId`, `status`                                 | D8 选择采用；`(surveyVersionId, questionId)` 唯一                        |

`library_option_keys` 按库内选项 ID 独立登记所属 libraryQuestionId，利用字符串 `_id` 唯一约束避免全局 ID 重复；不在题目身份中保存无限增长的已分配 ID 数组。只允许从选定来源版本继承 ID，新 ID 由服务端生成，另存新身份重新分配选项。

版本内容冗余在问卷快照中，用来隔离变化、保留历史并避免填写依赖题目库。身份文档只维护指针和可变元数据。当前原地编辑保存 contentRevision 和 updatedAt，不另存旧定义或逐次操作审计；不宣称能恢复每次未冻结修改；用户要求保留可恢复内容时选择创建新版本。

## 来源与稳定选项

```ts
interface QuestionSource {
  libraryQuestionId: string;
  questionVersionId: string;
  contentRevision: number;
  versionNumber: number; // 冻结版本号的显示快照
  optionSources: Array<{
    optionId: string; // 问卷实例选项
    sourceOptionId: string; // 题库内跨版本稳定的选项
  }>;
}
```

题目资源的 MongoDB `_id` 及 question_usages 中引用字段使用 ObjectId；问卷快照 source 中的资源引用保存规范 24 位字符串，与原共享题目类型一致，投影层显式转换。这样沿用原快照与纯函数读取方式，不让 ObjectId 类型进入共享包。现有 `questionId` 保持问卷实例含义，来源只能由服务端构建。公开填写的安全投影不输出 source，不能暴露授权元数据。版本内选项沿用相同语义的库内 `optionId`，新选项分配新 ID，删除不回收；普通客户端不能伪造或借用其他身份的选项 ID。实现前确定来源选项 ID 注册约束，避免不同分支把同一 ID 指向不同新选项。

首次选入来源结构时把目标草稿升为 `schemaVersion: 2`；未采用新结构的本地问卷可以继续使用 1，解除最后来源也不降级。读取兼容 1 和 2，不批量提升历史结构。`responses` 不新增题目库来源副本，原答案和实例 ID 无须迁移。

## 版本可修改条件与事务

不能只先查引用数再更新题库版本，否则检查与首次采用之间存在竞态。修改请求携带 `contentRevision`，以 `frozenAt: null` 加 revision 条件更新定义。首次采用、复制或派生在事务内条件写同一版本文档，设置永久 `frozenAt`，再读取并复制定义；与原地修改争用同一文档，冲突重试后重新检查状态和 revision。冻结与快照或新身份创建共同提交，失败回滚，不留下“已采用但仍可改”的状态。

新建版本和恢复在事务内分配版本号、冻结来源、插入新版本、更新身份指针；恢复同时稳定基线和恢复来源。原地改不分配新版本号。所有者与接收者都可以另存新身份，并保存源身份、版本和 revision；接收者不得以另存为由读未授权版本。

选入草稿继续复用题数上限、原有草稿 revision 和问卷修改时间事务。直接修改带来源定义必须转本地；排序和跳转保存必须保留来源；创建下一问卷草稿复制来源并登记新实例引用。发布快照不联动库内容。

## 授权与题库事务边界

批量授权限定用户名数量和版本数量，规范化去重；所有版本先验证属于当前所有者。未命中账号与重复账号保持统一受理响应，限流并记录不含敏感正文的摘要。授权管理仍有残余账号发现能力，文档如实说明。接收者只看获授权版本，不能通过版本链遍历未授权内容。

授权记录 `accessRevision` 支持选题或另存时的条件写入；与撤销删除争用同一记录，使两者按提交顺序生效。仅快照读取权限记录不足以声称撤销严格串行。已经留存快照不因撤销失效，仍可复制到下一问卷草稿；这属于已有问卷的延续，不借此恢复库访问或授权。

库成员的 latest 解析为最新可访问版本；pinned 校验属于相同身份且有权读取。更新库成员使用成员 revision，不修改任何问卷。不因成员引用就自动冻结版本，界面显示未冻结版本仍可原地修改。

## D8 两种反向引用方案

| 对比项   | A 快照多键索引                                                                              | B 独立使用记录                                        |
| -------- | ------------------------------------------------------------------------------------------- | ----------------------------------------------------- |
| 主查询   | 索引 `questions.source.libraryQuestionId` 或 `questionVersionId`，展开后关联 surveys 所有者 | 按身份或版本与 ownerId、status 过滤使用记录，再读快照 |
| 自己明细 | 需所有权关联后分页，检查过滤与展开代价                                                      | 可直接过滤，需再取快照标题和版本                      |
| 他人汇总 | 关联所有者后按用户、题目版本、状态分组                                                      | 直接按冗余 ownerId、版本、状态分组，批量补用户名      |
| 写入成本 | 来源随原快照写入                                                                            | 每个实例增加引用记录，所有变更需同事务维护            |
| 一致性   | 快照自身为事实来源                                                                          | 冗余需完整生命周期覆盖及核对修复工具                  |
| 适用验证 | 多键命中、展开、关联及分页扫描量                                                            | 复合索引、分组扫描量、事务操作数与修复成本            |

里程碑 1 用同一固定数据集比较：单身份多版本、同问卷多实例、多人共享、多草稿和历史发布版本，分别运行自己明细、他人汇总、统计来源解析。记录实际结果一致性、winningPlan、索引、返回数、keysExamined、docsExamined 和运行条件。只对独立实验库造数或建候选索引，不修改第一阶段业务库或提前接入业务实现。按证据与事务复杂度选择并记录理由，不只凭耗时决定。

若选择 B，选入、换题、转本地、删除题目、复制下一草稿、发布、放弃草稿均需维护；发布更新 status，放弃删除对应记录；题库成员变化不产生问卷使用。修复以问卷快照为准，不能从当前 usages 数量解除永久冻结。

D8 实验已经完成并选择 B，原始计划与成本说明见 `experiments/STAGE2_D8_COMPARISON.md`。里程碑 1 建立 usages schema 与索引；里程碑 2 已实现选入、换题、转本地、删除、发布、复制与放弃的同事务维护。排序和跳转不重复登记；以快照为准的运维核对与修复工具在最终回归里程碑整理。

## 跨问卷聚合路径

先在应用服务解析合法来源，形成有界映射：`surveyVersionId → questionId → 题目版本及选项映射`。自己引用先按问卷 ownerId 过滤，题目所有者看到他人使用汇总不代表可把这些来源带入统计。

再从 `responses` 执行以 `surveyVersionId` 为首要过滤的 `$match`，必要时加入 `answers.questionId` 与分页范围，沿现有版本索引读取；只展开或投影命中的答案，再按映射归一选项和题目版本。回答管道不执行 `$lookup` 回找问卷或题目库，也不全库展开回答后才过滤。来源集合过大时按版本与实例对分批，控制命令 BSON 和内存上限；不能用两个独立 `$in` 交叉匹配而错认不同版本实例。

计数、总和、极值和各桶计数可分批累加；平均值最终以总和除以有效回答数。文本分页需跨批稳定合并，游标绑定用户、身份、选中版本集合、筛选和排序；数字分桶绑定边界，保证分页或刷新不混用条件。统计与来源解析采用一致读视图，不能把分批读取天然当成同一快照。

默认各题目版本分开，勾选同一身份版本后合并。按源选项 ID 计数并显示文字差异；数值边界严格递增且有限，设桶数上限，采用 `$bucket` 或等价条件聚合。对未覆盖上下界分别计数，边界等值左闭右开，空回答单独统计，桶总数与回答数核对。跨版本检查题型，展示标题、必答、选项、校验差异后需明确确认，不能据同题型自动宣称语义一致。

## 接口与前端范围

拟在题目资源下提供创建、原地更新、新版本、恢复、另存、版本级批量授权、引用明细与脱敏汇总。题库成员提供 versionPolicy 与固定版本更新。跨问卷统计接口支持单版本或明确的版本集合、差异预览与确认、数字分桶边界和安全分页。最终 HTTP 方法、参数上限、错误顺序、状态码和响应字段在相应里程碑设计并同步 `API.md`。

修改题目前先展示实际使用与冻结状态，服务端再次检查；不能仅依赖界面决定可否覆盖。所有接口复用认证、Origin、JSON、限流与错误结构，资源越权与不存在保持一致。回归继续覆盖旧会话、旧答案、匿名投影、跳转和事务不变量。

## 里程碑 2 已实现行为

四个新增问卷接口见 API 文档，均先检查原问卷所有权、草稿状态和 revision。选题与换版本校验所选库版本 contentRevision，并与首次采用冻结争用同一版本文档。来源冻结、快照、使用记录和问卷修改时间在同一 session 中提交；失败全部回滚。

来源题的普通定义 PATCH 返回 LIBRARY_SNAPSHOT_READ_ONLY，需显式转本地。换版本在原位置创建新实例，先处理入站引用及出站规则；转本地保留原实例 ID、选项 ID 与规则。保存本地题入库则只创建新资源并递增草稿 revision，不给当前问卷自动增加来源，也不重写历史回答。

前端新增具体版本选择与内容预览，换版本时把本地选项映射回来源选项后比较，避免把不同实例 ID 误报为版本内容变化。来源题定义只读，排序和局部跳转保留可配置。题目、设置或规则尚未保存时先禁用常用题目操作，避免换实例造成未保存规则丢失。公开填写继续采用原安全投影，不输出 source。

实际自动检查和人工步骤见 `experiments/STAGE2_MILESTONE2_TEST_REPORT.md`，尚未代用户确认人工验收。

## 里程碑 3 已实现行为

question_shares 每个接收者及版本一条记录，唯一键防止重复授权；接收者只能看到选定版本和可见祖先，身份最新指针与版本计数限定到授权范围。批量授权及撤销使用题目身份 revision 串行化管理；选入与另存条件写精确授权记录的 accessRevision，与撤销删除争用，失败时一起回滚。普通在途读取不追溯取消，但后续新增使用受事务保护。

自己的引用从 usages 找候选，再核对自己拥有的问卷与真实快照，返回可定位明细。他人汇总仅题目所有者可读，严格只输出用户名、版本、数量和状态；其复合分页键使用独立派生 AES-GCM 密钥加密，不通过签名 Base64 透出用户 ID。回答统计权限不变。

前端包含“共享给我”、所有者多版本批量授权与撤销、接收者只读与另存、自己引用定位及他人受限汇总。详细接口和实际检查见 API 与 `experiments/STAGE2_MILESTONE3_TEST_REPORT.md`。

## 当前版本优先的界面

管理页默认读取 latestVersionId 指向的当前版本；接收者仍以最新获授权版本为可见当前，不获得私有最新版本。历史列表改为按钮展开后加载和选择，来源与比较也收在历史区域。查看历史时隐藏编辑与共享面板，恢复成功后关闭历史并展示新生成的当前版本。

共享面板不再读取全部版本或维护复选框，只把当前版本 ID 传入已有授权接口，仍可批量填写用户名。问卷选题默认获取当前可访问版本，历史只有显式展开后才可选；不再为了避开已用版本而自动选中某个旧版本。该调整属于交互默认与可见操作变化，保留原数据结构、冻结保护及显式版本 API。

## 里程碑 4 已实现题库分类

新增私有 question_banks 与 question_bank_items。题库索引 `(ownerId, _id desc)`，成员唯一索引 `(bankId, libraryQuestionId)` 和列表索引 `(bankId, _id desc)`。一个题目身份可存在于多个题库；成员文档独立存储，避免题库内嵌数组无限增长。库名 1–80 字，列表默认 20、最多 50，分页游标绑定用户与库。

题库 revision 用于改名和删除；每个成员单独 revision 用于策略修改及移出。成员变更在事务中写父库 membershipRevision，与删除父库争用，避免删除与加入并发导致孤儿。重复加入通过先查及唯一键双重保护，以 BANK_CONFLICT 反馈；事务回滚父库写和授权写。

latest 在每次读取时解析当前可访问版本，共享题只选择最高获授权版本。pinned 固定某个版本身份，不把未冻结定义自动变成不可变。授权撤销后的 pinned 显示不可用，不自动换另一个有权版本；全部授权失效时 latest 同样显示不可用。读取复用 LibraryService.get 的权限、来源脱敏和字段投影；有界页逐成员解析，仍有每页多次查询成本，尚未进行大规模题库性能基准，不把 D8 实验当作本接口性能证明。

分类本身不冻结、不改变使用记录；版本更新、移出、删除只作用于分类。共享成员加入和更新事务触碰精确授权记录，与撤销串行化；真正选入问卷仍重新检查权限与内容修订。题库私有，不通过题库扩展共享范围。

前端增加题库管理页和问卷选题器分类入口。明确选取的版本默认固定，用户可切换跟随最新并同步预览最新内容；成员设置展示新旧定义差异，历史仍需主动展开。按题库选题直接采用成员解析后的版本，不调用“加载当前”覆盖固定旧版本。题库的更新不会替换问卷里的快照，问卷需另行明确换版本。

## 里程碑 5 已实现跨问卷单题统计

按当前用户、同一 libraryQuestionId 查询发布 usages 候选，再核对真实问卷所有者、发布快照与来源版本，归一实例选项至源 ID。定义取自自己的不可变快照，不依赖撤销后的题库读取权限；题目所有者不会因此看到接收者回答。一个身份最多 1000 条候选、一次选择最多 50 个版本；超限明确错误，缺失投影留给核对修复工具，不按标题补认来源。

统计以题目实例为单位，提交量乘以相关实例数形成机会数，路径和实际答案分别给出到达与已答。默认分版本，显式确认后合并同身份版本。选择按稳定源 ID 合并并保留不同文字，数字累加 count/sum/extrema 再计算平均，按自定义边界条件聚合分桶（包含上下界外桶），避免逐值计频。文本以同一提交里的不同实例分别返回，统一隐藏账号与精确时间。

来源读取和每 50 实例一批的回答聚合处于同一 snapshot 事务。回答管道先 match 有权版本、再只提取该版本对应的实例，不执行 lookup。文本批内取 limit+1 后全局合并，来源键解决同一响应多实例的排序平局；应用层采用二进制字符比较，与 MongoDB 一致，避免 localeCompare 对大小写或符号顺序不同引起漏页。加密游标绑定用户与完整查询条件及来源集合，来源增加后要求重查。

前端统计默认折叠，常用题目详情、草稿来源题及已发布问卷来源题均可进入。勾选版本、预览差异并确认合并；数字支持分桶输入、次数表和 meter 分布。改变筛选会清除旧结果及合并确认，避免把旧结果误当作新口径。共享撤销后仍能从自己的问卷入口查看留存回答。

独立实验在 MongoDB 8.0.34 的 7000 份回答上运行真实聚合：20 个有权实例对应 1000 份回答，得到 2000 次有效数值、总和 99000。来源索引扫描 20 键/20 文档，回答索引扫描 1001 键/1000 文档；完整 explain 和运行条件已保存。不将该小规模结果外推为生产负载保证。自动与人工检查见里程碑 5 记录。

## 里程碑 6 核对 修复与演示

使用投影核对以 surveys 所有权及 survey_versions 实际来源为唯一重建依据；检查库版本存在、冻结、修订及归一选项定义。生成绑定预期、实际、来源修订及异常的 planHash；只允许指定问卷并显式传入该值修复。修复与正常写同一父问卷 updatedAt，形成争用，事务重试后重新计算计划；版本和回答不动，clean 无写入，孤立或异常来源不自动创造或删除资源。实际并发和写后故障回滚测试已验证。

第二阶段演示独立使用 stage2_teacher/student/outsider，manifest 先与账号原子创建以记录 building 状态，业务数据逐步生成完成后标记 ready。中断不自动覆盖；默认重跑仅验证；显式清理按 manifest 账号 ID 收集资源，检测外部使用/复制/分类/授权后才在同事务内删除。正式回答走原填写服务；不重置用户原有种子和手工验收数据。原 seed 加第二阶段数据预检，维护命令仅本地非生产可运行。

统一测试清理列出业务 12 集合与演示 manifest，并验证当前连接确为声明的 `_test` 数据库。原始无来源快照、答案与旧统计做前后比较，不重写旧数据。需求矩阵、完整回归、CLI 输出、清理计数及人工验收见里程碑 6 实验记录；最终报告仍须后续单独完成。
