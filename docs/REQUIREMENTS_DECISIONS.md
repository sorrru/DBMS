# 第一阶段需求决策记录

## 文档目的

本文记录基于初始用户需求说明完成的人工澄清和业务决策。它是第一阶段系统设计与后续实现的依据，也是人与 AI 分阶段协作过程的真实记录。本文只记录已经讨论并由项目负责人确认的内容，不把尚未实现的功能标记为完成。

## 固定需求范围

第一阶段必须完成：

- 用户注册和登录。
- 用户创建并管理自己的问卷。
- 问卷发布、关闭、截止时间和公开访问链接。
- 单选题、多选题、文本填空题和数字填空题。
- 必答、选择数量、文本长度、数字范围和整数校验。
- 单选、多选和数字答案的条件跳转。
- 保存每次正式提交。
- 按题目生成统计结果。
- 使用 MongoDB 保存业务数据。
- 实现前端、后端、测试、项目文档和完整报告。
- 真实记录 AI 提示词、产出、人工检查和修改过程。

## 身份和匿名

### 登录要求

所有填写者都必须登录，包括选择匿名填写的用户。

### 匿名的正式定义

匿名表示“对问卷创建者匿名”，不是“对系统完全匿名”。

- 系统需要识别同一填写者，以执行重复提交限制。
- 匿名回答不直接保存用户 UID。
- 系统使用不可逆的问卷内匿名标识识别填写者。
- 创建者不能看到 UID、用户名、问卷内匿名标识或其他可关联身份的信息。
- 不同问卷中的匿名标识不同，创建者不能跨问卷关联同一用户。

建议计算方式：

```text
respondentKey = HMAC-SHA256(ANONYMOUS_ID_SECRET, surveyId + ":" + userId)
```

匿名标识密钥与登录令牌密钥分开管理，且不能提交到 Git 仓库。

### 非匿名填写

如果问卷版本配置为非匿名，系统可以在回答中关联填写者账号，并允许创建者查看对应用户名。

## 重复填写

- 问卷创建者可以设置是否允许重复填写。
- 该设置属于具体问卷版本。
- 不允许重复填写时，同一用户对同一个版本只能提交一次。
- 用户填写过 v1 后，仍可填写 v2。
- 允许重复填写时，同一用户可以对该版本提交多次。
- 匿名模式同样使用问卷内匿名标识判断是否为同一用户。

## 问卷版本

### 发布后修改流程

已发布版本不可直接修改。创建者修改问卷时采用以下流程：

```text
当前发布版本继续提供填写
        ↓
从当前版本创建下一版本草稿
        ↓
编辑并人工检查草稿
        ↓
再次发布
        ↓
新版本成为当前版本，旧版本保留
```

### 版本隔离

- 每份回答必须关联具体问卷版本。
- 不同版本的回答不能自动混合统计。
- 旧版本的题目、规则、回答和统计必须保留。
- 在新版本中删除题目，不得删除旧版本中的题目或历史回答。
- 发布新版本不会更换问卷公开链接。

### 正在填写旧版本的用户

- 用户打开问卷时创建填写会话，并固定到当时的发布版本。
- 填写会话默认有效期为 30 分钟。
- 有效期内即使发布了新版本，用户仍可提交到原版本。
- 新打开问卷的用户始终进入最新发布版本。
- 回答计入其填写会话绑定的版本。

## 问卷关闭和自动到期

- 手工关闭与自动到期不是同一种状态。
- 手工关闭显示为“已关闭”。
- 超过版本截止时间显示为“已到期”。
- 手工关闭后立即禁止创建填写会话和提交回答。
- 自动到期后立即禁止创建填写会话和提交回答。
- 发布新版本不会自动重新打开已经手工关闭的问卷。
- 创建者可以手工重新开放问卷，但重新开放不能绕过已经过去的截止时间。

## 跳转规则

- 跳转规则按保存顺序从上到下检查。
- 多条规则同时满足时，第一条规则生效。
- 没有规则满足时，进入按顺序排列的下一题。
- 发布前必须检查跳转目标是否存在。
- 发布前必须检查跳转规则是否形成循环。
- 存在循环时禁止发布。
- 不可到达题目可以产生警告，但不强制阻止发布。

## 被跳过的必答题

必答只对本次实际答题路径上的题目生效。

- 跳转绕过的必答题不需要回答。
- 跳转到的必答题必须回答。
- 用户修改前面答案导致路径变化时，前端清除新路径之外的旧答案。
- 后端重新计算最终路径，不信任前端传入的路径。
- 后端不保存路径之外的答案。
- 提交结果可以返回被忽略的题目编号。
- 每份回答保存实际经过的 `questionPath`。
- 统计同时显示经过题目的人数和实际回答人数。

示例：

```text
Q1 选择 A 后跳到 Q3
Q2 是必答题

本次实际路径：Q1 → Q3
```

此时 Q2 不校验，也不保存答案。

## 手机号字段

手机号使用文本类型存储，不使用整数类型。

理由：

- 手机号是标识符，不参与数值计算。
- 数字类型可能丢失前导零。
- 国际号码可能包含国家区号。
- 长号码可能超过部分语言的安全整数范围。

建议校验结构：

```json
{
  "type": "text",
  "validation": {
    "digitsOnly": true,
    "minLength": 11,
    "maxLength": 11
  }
}
```

年龄等真正用于比较和计算的数据继续使用数字题，并支持整数、最小值和最大值校验。

## 统计规则

- 统计必须指定问卷版本。
- 不同版本默认分别展示，不自动合并。
- 每道题至少显示 `reachedCount` 和 `answeredCount`。
- 单选题统计每个选项的选择人数。
- 多选题统计每个选项被选择的次数。
- 文本题分页查看填写内容。
- 数字题显示填写值、平均值、最小值和最大值。
- 后续如需跨版本比较，只能比较题目 ID 和题型仍兼容的题目，并明确标注版本。

## 人与 AI 决策过程

### 第一轮 人工澄清需求

AI 列出初始需求中存在的歧义。项目负责人逐项决定：

- 匿名填写仍要求登录。
- 创建者需要重复填写开关。
- 发布后修改采用问卷版本。
- 手工关闭和自动到期使用不同状态。
- 跳转冲突取第一条。
- 发布时禁止跳转循环。
- 删除题目通过新版本完成。

### 第二轮 匿名和版本边界

AI 指出“不保存身份”与“系统判断同一用户”存在冲突。项目负责人确认采用问卷内匿名标识，并决定重复填写限制按版本计算。

### 第三轮 旧版本会话与边界规则

项目负责人采用 R1 至 R6：旧版本填写会话保留 30 分钟、新用户进入最新版、统计按版本分开、关闭与到期分别处理、发布不自动重新开放、匿名身份不向创建者暴露。

### 第四轮 必答路径和手机号

项目负责人采用 A1 至 A7，并确认手机号使用字符串加数字字符校验。这是人工检查对初始需求文字作出的数据建模修正。

## 当前结论

上述规则已经过人工检查并确认，可作为系统设计、数据库结构、API、测试和项目报告的业务基线。后续实现发现新的歧义时，应追加决策记录，不能静默改变本文结论。
