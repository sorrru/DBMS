# 里程碑 10：种子数据核算与幂等验证

## 演示数据范围

种子脚本使用三个固定账号，密码均取运行时的 `SEED_USER_PASSWORD`：

- `seed_demo`：问卷创建者；
- `seed_guest_a`：实名与匿名填写者甲；
- `seed_guest_b`：实名与匿名填写者乙。

脚本创建 3 份问卷、4 个版本、6 个填写会话和 5 份正式回答：

| 问卷                 | 版本和状态                | 会话 / 回答                                               | 用途                                       |
| -------------------- | ------------------------- | --------------------------------------------------------- | ------------------------------------------ |
| 匿名课程反馈（种子） | 已发布 v1 + 草稿 v2       | 3 个已提交会话与回答，另有 1 个已过期但待惰性回收的旧会话 | 四题型、两条路径、禁止每版本重复、版本隔离 |
| 实名活动报名（种子） | 已发布 v1，手工关闭       | 2 个账号各 1 个已提交会话与回答                           | 实名账号、批量用户查询、允许重复           |
| 已到期问卷（种子）   | 已发布 v1，截止时间在过去 | 无                                                        | 自动到期状态                               |

匿名会话与回答不保存 `userId` 或 `respondentId`；实名回答分别关联 `seed_guest_a` 与 `seed_guest_b`。清理只识别这三个保留用户名及 `seed_demo` 拥有的问卷，不接受命令行传入任意用户或问卷范围。

## 匿名问卷的手算预期

三份 v1 回答如下：

1. 满意；课堂讲解 + 课程实验；联系电话 `13800138000`；每周 8 小时；
2. 一般；课程实验；联系电话不答；每周 12 小时；
3. 不满意；规则直接跳到学习时长；每周 6.5 小时。

因此统计应为：

| 题目         | 提交 | 到达 | 回答 | 未到达 | 到达未答 | 其他预期                                           |
| ------------ | ---: | ---: | ---: | -----: | -------: | -------------------------------------------------- |
| 整体满意度   |    3 |    3 |    3 |      0 |        0 | 满意、一般、不满意各 1                             |
| 有帮助的内容 |    3 |    2 |    2 |      1 |        0 | 课堂讲解 1、课程实验 2、课后讨论 0                 |
| 联系电话     |    3 |    2 |    1 |      1 |        1 | 仅 1 条匿名文本回答，界面只显示 UTC 日期           |
| 每周学习时长 |    3 |    3 |    3 |      0 |        0 | minimum 6.5、maximum 12、average 8.833333333333334 |

统计必须固定读取已发布 v1，不能混入内容相同但尚未发布的 v2 草稿。

## 实名问卷的手算预期

实名问卷共有 2 份提交。必答“姓名”题到达 2、回答 2、未到达 0、到达未答 0。文本分页应显示：

- `seed_guest_a`：种子甲；
- `seed_guest_b`：种子乙。

创建者仍可查看关闭问卷的既有统计；关闭只禁止新的填写会话和提交。

## 两次生成与两次清理

2026-10-20 在本地 Docker MongoDB 8.0.34 的 `survey_stage1` 数据库实际执行。两次 `npm run seed` 都先清理自身旧数据，再得到完全相同的计数：

```json
{ "users": 3, "surveys": 3, "versions": 4, "sessions": 6, "responses": 5 }
```

第一次 `npm run seed:clean` 实际删除：

```json
{ "users": 3, "surveys": 3, "versions": 4, "sessions": 6, "responses": 5 }
```

第二次 `npm run seed:clean` 实际删除：

```json
{ "users": 0, "surveys": 0, "versions": 0, "sessions": 0, "responses": 0 }
```

这证明生成结果稳定、执行前自清理有效、清理覆盖全部五类关联数据且空库重复清理幂等。验证结束后，使用项目现有 `.env` 再生成一次同样的演示数据，留给人工端到端验收。
